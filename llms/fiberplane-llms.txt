## What is fp?

fp is a local-first CLI for tracking work when coding with AI agents, especially Claude Code. It gives both humans and AI agents a shared place to plan tasks and log progress without losing context between sessions.

Issue data is stored locally in `~/.fiberplane/projects/<storage-dir>/` (SQLite). The project itself is registered globally in `~/.fiberplane/projects.toml`. No external services, no MCP server required.

## The Problem fp Solves

When using AI coding agents like Claude Code:
1. Context disappears when you clear sessions or hit compaction limits
2. Tracking what an agent worked on across multiple sessions is tedious
3. Agents scatter random markdown files throughout your codebase

fp provides structure: issues persist across sessions and progress is logged on the issues themselves.

## Key Capabilities

1. Issue Hierarchy: Break work into parent/child tasks with dependencies
2. Agent integration: `fp init --agent standard` writes `FP_AGENTS.md` and ensures `AGENTS.md` `@`-includes it; any agent that reads `AGENTS.md` loads the workflow automatically. Use `--agent claude` (or run `fp agent setup claude` later) to write Claude-specific `FP_CLAUDE.md` / `CLAUDE.md` files instead. fp does not install Claude skills, hooks, settings, or permissions — the integration is entirely through these instruction files.
3. Context Loading: `fp context <id>` outputs issue details for agent consumption
4. Local-first storage: Issue data lives on the developer's machine; agent integration files can be committed to the repo

## Workflow Primers

Workflow primers are bundled in the binary and printed by `fp guide`:

fp guide plan: Create implementation plans from descriptions, GitHub issues, Linear issues, or Notion pages
fp guide implement: Work through issues following the Find → Claim → Work → Comment → Complete cycle
fp guide brainstorm: Author rich brainstorm plans with markdown + Mermaid (alias: bs)
fp guide extension: Write fp extensions (lifecycle hooks, custom properties)

Pipe the output into your agent or print for review. `--references <name>` surfaces companion material (e.g. `fp guide brainstorm --references mermaid`).

## Quick Start

```bash
curl -fsSL https://setup.fp.dev/install.sh | sh -s  # Install
cd your-project
fp init                                              # Register, scaffold .fp/, prompt for agent setup, seed onboarding tasks
# fp init --agent standard                           # Same, plus FP_AGENTS.md + AGENTS.md
# fp init --agent claude                             # Same, plus FP_CLAUDE.md + CLAUDE.md for Claude Code
```

Then paste into your agent: "Pick up the seeded fp onboarding tasks. Run `fp tree` to see them and work the children one at a time."

## Essential Commands

fp init: Register the project, scaffold `.fp/`, prompt for agent instruction setup, and seed onboarding issues on the first-ever project. Accepts `--agent claude|standard|codex|skip` to pick the agent surface non-interactively.
fp agent setup <claude|standard|codex>: Add or refresh agent instruction files in an already-initialized project (idempotent). `claude` writes `FP_CLAUDE.md` + ensures `CLAUDE.md` `@`-includes it; `standard` and `codex` write `FP_AGENTS.md` + ensure `AGENTS.md` `@`-includes it.
fp guide [skill]: Print bundled workflow primers (plan, implement, brainstorm, extension)
fp update: Install the latest stable release (add --latest for prereleases)
fp issue create --title "...": Create a new issue
fp issue list [--status todo]: List issues with optional filters
fp tree: View issue hierarchy as ASCII tree
fp context <id>: Output issue context (for Claude)
fp run <id>: Dispatch Claude to work on an issue
fp comment <id> "message": Add a progress comment

## Typical Workflow

1. Plan: "use fp to break down the auth feature"
   Claude creates hierarchical issues
2. Work: "pick up AUTH-abc"
   Claude marks in-progress, starts coding, comments at milestones, marks done
3. Reset: `/clear` and start next task
   Context preserved via fp for the new session
